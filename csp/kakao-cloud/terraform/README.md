# Narwhal IDP on Kakao Cloud - Terraform Infrastructure

English | [Korean](README.ko.md)

OpenTofu project that provisions VM infrastructure on Kakao Cloud for the Narwhal IDP cluster.
Kubernetes and the platform apps are installed afterwards by
[`scripts/cloud/provision-kakao.sh`](../../../scripts/cloud/provision-kakao.sh).

Verified end to end on 2026-07-27: 6/6 nodes Ready, 33 ArgoCD applications Synced/Healthy,
services reachable through the worker LB.

## What Gets Created

| Resource | Count | Description |
|----------|-------|-------------|
| VPC | 1 | 172.16.0.0/16 |
| Subnet | 1 | 172.16.0.0/24 |
| Security Group | 1 | K8s + Cilium + NFS + proxy/registry ports |
| Master VMs | 3 | Control-plane (t1i.large, 2 vCPU / 4GB), fixed **private** IPs .10 .11 .12 |
| Worker VMs | 3 | Data-plane (t1i.xlarge, 4 vCPU / 8GB), fixed **private** IPs .21 .22 .23 |
| Bastion VM | 1 | SSH jump host, forward proxy, airgap registry (public + private .207) |
| Master LB | 1 | K8s API (6443) + etcd (2379) |
| Worker LB | 1 | Ingress HTTP (80) + HTTPS (443) -> NodePort 31080/31443 |
| Public IPs | 3 | Bastion + 2 LBs. **Cluster nodes have none** |

Nodes are private by design. Everything reaches them through the bastion, and their
outbound traffic goes through a squid proxy running there — Kakao Cloud provider 0.4.4
exposes no NAT gateway resource, and giving each node a public IP would expose the SSH
and 6443 rules this security group opens to 0.0.0.0/0. `assign_node_public_ips = true`
is the escape hatch if you need direct egress instead.

## Architecture

```
                            Internet
                                |
        +-----------------------+-----------------------+
        |                       |                       |
    Bastion                 Master LB               Worker LB
  public IP (+priv .207)   public IP :6443       public IP :80/443
  ssh · squid:3128            |                       |
  registry:5000               |                       |
        |                     |                       |
        |  ProxyJump          | private VIP .236      | private VIP .110
        |  (admin access)     |                       | -> NodePort 31080/31443
        v                     v                       v
   +---------------------------------------------------------+
   |  > Nodes hold private addresses only - no public IP      |
   |                                                          |
   |  master-1 .10   master-2 .11   master-3 .12              |
   |  worker-1 .21   worker-2 .22   worker-3 .23              |
   |                                                          |
   |  egress -> bastion squid:3128                            |
   +---------------------------------------------------------+
                    VPC 172.16.0.0/16 · Subnet 172.16.0.0/24
        (every .xx above is a 172.16.0.xx private address)
```

## Prerequisites

- **OpenTofu** >= 1.6.0 (`tofu`; Terraform CLI also works)
- **Kakao Cloud Account** with Application Credential (ID + Secret)
- **Quotas**: 7 instances, 26 vCPU, 52GB+ RAM, 1.2TB volume, 3 public IPs, 2 LBs

The SSH keypair is generated by this project (`tls_private_key` + `kakaocloud_keypair`)
and written to `var.ssh_key_path`; you do not pre-register one.

## Quick Start

```bash
cd csp/kakao-cloud/terraform

cp terraform.tfvars.example terraform.tfvars
# Fill in application_credential_id / application_credential_secret

tofu init
tofu plan
tofu apply
```

Then, from the repo root, bring up the cluster:

```bash
./scripts/cloud/stage-kakao-nodes.sh     # repo -> nodes, in the layout the scripts expect
./scripts/cloud/provision-kakao.sh all   # base -> mirror -> init -> join -> nfs -> phase1 -> phase2
```

`provision-kakao.sh` reads every address from OpenTofu state, so nothing is typed twice.
Stages are idempotent (sentinels under `/home/vagrant/.narwhal-stage/`); `FORCE=1` re-runs one.

## After Deployment

Nodes have no public IP, so all access is through the bastion:

```bash
tofu output bastion_ssh          # ready-made ssh / ProxyJump commands
tofu output -raw bastion_public_ip

ssh -i "$(tofu output -raw ssh_key_path)" \
    -J ubuntu@"$(tofu output -raw bastion_public_ip)" \
    ubuntu@"$(tofu output -json master_private_ips | jq -r '.[0]')"
```

`master_public_ips` and `worker_public_ips` are empty arrays unless
`assign_node_public_ips` is on — that is expected, not a failure.

## Directory Structure

```
terraform/
  main.tf              # Root: network -> security -> compute -> loadbalancer
  bastion.tf           # Jump host + its public IP
  variables.tf         # Variable definitions
  outputs.tf           # Node IPs, LB endpoints, bastion, ssh_key_path, subnet_cidr, vpc_cidr
  provider.tf          # kakaocloud provider v0.4.4
  cloud-init.yaml      # Basic VM init (SSH pubkey only)
  terraform.tfvars.example
  modules/
    network/           # VPC + Subnet
    security/          # Security Group
    compute/           # Master/Worker VMs (fixed private IPs) + optional public IPs
    loadbalancer/      # Master LB (6443/2379) + Worker LB (80/443)
```

## Configuration

Key settings in `terraform.tfvars`:

| Variable | Default | Description |
|----------|---------|-------------|
| `master_count` | 3 | Master nodes (3 for HA) |
| `worker_count` | 3 | Worker nodes |
| `master_flavor` | t1i.large | 2 vCPU, 4GB RAM |
| `worker_flavor` | t1i.xlarge | 4 vCPU, 8GB RAM |
| `volume_size` | 200 | Disk size in GB |
| `availability_zone` | kr-central-2-a | Kakao Cloud AZ |
| `assign_node_public_ips` | false | Direct egress per node instead of the bastion proxy |

Node IPs are pinned contiguously (`cidrhost` on `subnet_cidr`) so the install scripts'
`${MASTER_IP_BASE}${idx}` arithmetic resolves the same way it does under Vagrant.

## Security Group Ports

| Port | Source | Purpose |
|------|--------|---------|
| 22 | 0.0.0.0/0 | SSH |
| 6443 | 0.0.0.0/0 | Kubernetes API |
| 80, 443 | 0.0.0.0/0 | Ingress via worker LB |
| 2379-2380 | VPC | etcd |
| 10250, 10251 | VPC | kubelet / scheduler |
| 111, 2049 | VPC | NFS (rpcbind, nfsd) |
| 4240, 4244, 8472 | VPC | Cilium health, Hubble, VXLAN |
| 3128 | VPC | Bastion squid forward proxy |
| 5000 | VPC | Airgap bootstrap registry |
| 30000-32767 | VPC | NodePort range |

22 and 6443 are open to the internet. They are only reachable through the LBs while the
nodes stay private; narrow them to your operator address if you turn on
`assign_node_public_ips`.

## Known Issues

None open in this project. Two behaviours worth knowing before you debug something else:

- **Load balancers must not be created before the instances.** A `kakaocloud_load_balancer`
  takes its private VIP from the same subnet by automatic allocation, `private_vip` is
  computed and cannot be pinned, and `kakaocloud_subnet` exposes no allocation pool. An LB
  created first will take an address the compute module pinned — that is why
  `module.loadbalancer` carries `depends_on = [module.compute]`.
- **A module-level `depends_on` also defers that module's data sources to apply time.**
  Adding one security group rule once planned as a full rebuild of every running instance,
  because `data.kakaocloud_images` became unknown and `image_id` forced replacement. Keep
  those lists as narrow as the real dependency.

Provisioning-side issues (the container runtime, unattended-upgrades, NFS) are documented
in [`docs/lessons-log.md`](../../../docs/lessons-log.md).
